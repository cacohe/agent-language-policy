# Content Classification

## Human decision content

Use the configured target language for conversation, progress updates, clarification questions, approach comparisons, architecture explanations, specifications, implementation plans, task descriptions, tradeoffs, risks, review findings, test-result explanations, approval requests, and final summaries.

## Technical literals

Preserve source code, identifiers, APIs, type names, function names, variable names, paths, commands, flags, package and dependency names, configuration keys, environment variables, protocols, logs, stack traces, and original errors.

## Project-owned content

README files, product documentation, UI copy, comments, docstrings, commit messages, pull-request content, changelogs, and public API documentation follow the current user request, repository conventions, intended audience, and existing file language.
