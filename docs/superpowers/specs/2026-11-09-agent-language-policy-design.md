# Agent Language Policy 设计说明

## 目标

构建一个跨编码 Agent 的语言策略产品：所有用于人类理解、判断、批准和控制软件开发工作的内容使用用户选择的目标语言；代码、命令、路径、API、标识符、依赖名称、日志和原始错误保持英文或原文；项目拥有的 README、产品文案、代码注释和公开文档继续遵循项目约定。

首个版本默认支持简体中文（`zh-CN`）和韩文（`ko-KR`），同时保留以后扩展其他 BCP 47 语言标签的结构。

## 非目标

- 不承诺模型层面百分之百服从自然语言指令。
- 不自动翻译现有项目文档或产品文案。
- 不修改源代码、标识符、日志或错误信息的语言。
- 不依赖 MCP 服务或远程账户。
- 第一版不拦截或改写聊天输出，只通过常驻指令提高一致性，并校验写入文件的 Markdown 方案文档。

## 架构

产品分为四层：

1. 标准 Agent Skill：提供可移植的语言分类、优先级和审批前检查规则。
2. 统一配置：保存目标语言、技术字面量策略和项目产物策略。
3. 安装器与适配器：把短小的常驻规则安全写入 Codex、Claude Code、Cursor、Gemini CLI 和 GitHub Copilot 的原生指令文件。
4. 文档校验器：分析 Markdown 的说明性正文，排除代码块、行内代码、路径、URL 和技术字面量后检查目标语言。

## 内容分类

### 人类决策内容

对话、进度说明、澄清问题、方案比较、架构设计、设计规格、实施计划、任务说明、风险与取舍、审查结论、测试结果解释、审批请求和最终总结使用目标语言。

### 技术字面量

代码、标识符、类型名、函数名、API、协议、文件路径、命令、参数、包名、依赖名、配置键、环境变量、SQL、正则表达式、日志、错误和堆栈保持原文。

### 项目拥有的内容

README、用户文档、产品 UI 文案、代码注释、docstring、commit message、PR 内容、changelog 和公共 API 文档遵循当前用户要求、项目规则、受众和已有文件语言。

## 指令优先级

1. 当前用户对具体产物的明确要求。
2. 项目或组织的语言政策。
3. 产物的目标受众及已有文件语言。
4. 用户级目标语言。
5. Skill 或模板原本使用的语言。

## 安全和可恢复性

安装器只管理带开始和结束标记的区块。安装、更新和卸载必须保持幂等，不覆盖文件中的其他内容；实际写入前支持预览；修改已有文件前创建备份；卸载只移除自己的托管区块。

## MVP 支持范围

- 语言：`zh-CN`、`ko-KR`。
- 作用域：项目级、用户级。
- Agent：Codex、Claude Code、Cursor、Gemini CLI、GitHub Copilot。
- 运行时：Node.js 20 或更高版本，使用内置模块，首版不依赖第三方运行时包。
- 校验对象：Markdown 设计、规格、架构、计划和审查报告。

## 验收标准

- 核心 Skill 满足 Agent Skills 的 `SKILL.md` 目录格式。
- 外层包含符合 Agent Plugins 结构的 `plugin.json`。
- 安装器能够检测、预览、安装、更新、查看状态、诊断和卸载。
- 中文配置生成中文人类决策规则，韩文配置生成韩文人类决策规则。
- 技术字面量和项目产物的例外规则在两种语言中保持一致。
- 重复安装不会产生重复区块。
- 卸载不会删除用户原有内容。
- 校验器能识别纯英文方案正文不符合 `zh-CN` 或 `ko-KR`，并忽略代码和技术字面量。
